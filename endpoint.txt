ENDPOINT TEST AND IMPLEMENTATION

1. Create a new inventory transaction
   Endpoint: POST /api/v1/inventory/transactions/
   Request Body:
   {
     "product_id": 1,
     "warehouse_id": 1,
     "quantity": 10,
     "transaction_type": "stock_in",
     "reference_number": "PO-001",
     "notes": "Initial stock"
   }
   Response:
   {
     "id": 1,
     "product_id": 1,
     "warehouse_id": 1,
     "quantity": 10,
     "transaction_type": "stock_in",
     "reference_number": "PO-001",
     "notes": "Initial stock",
     "tenant_id": 1,
     "created_at": "2025-09-19T10:00:00Z",
     "updated_at": "2025-09-19T10:00:00Z"
   }

2. Get transactions for a specific product
   Endpoint: GET /api/v1/inventory/transactions/product/{product_id}
   Query Parameters:
   - start_date (optional): Filter by start date
   - end_date (optional): Filter by end date
   - transaction_type (optional): Filter by type
   - skip (optional, default=0): Pagination offset
   - limit (optional, default=100): Page size
   Response:
   [
     {
       "id": 1,
       "product_id": 1,
       "warehouse_id": 1,
       "quantity": 10,
       "transaction_type": "stock_in",
       "reference_number": "PO-001",
       "notes": "Initial stock",
       "created_at": "2025-09-19T10:00:00Z"
     }
   ]

3. Get summary of inventory transactions
   Endpoint: GET /api/v1/inventory/transactions/summary/
   Query Parameters:
   - start_date (optional): Filter by start date
   - end_date (optional): Filter by end date
   Response:
   {
     "total_transactions": 100,
     "total_stock_in": 1000,
     "total_stock_out": 800,
     "net_change": 200,
     "transaction_types": {
       "stock_in": 50,
       "stock_out": 40,
       "adjustment": 8,
       "transfer": 2
     }
   }

4. Get recent inventory transactions
   Endpoint: GET /api/v1/inventory/transactions/recent/
   Query Parameters:
   - limit (optional, default=10): Number of recent transactions to retrieve
   Response:
   [
     {
       "id": 100,
       "product_id": 1,
       "warehouse_id": 1,
       "quantity": 5,
       "transaction_type": "stock_out",
       "reference_number": "SO-001",
       "notes": "Order fulfillment",
       "created_at": "2025-09-19T09:45:00Z"
     }
   ]

Implementation Notes:
- All endpoints require authentication
- All endpoints enforce tenant isolation
- Transactions are immutable once created
- Stock levels are automatically updated
- All dates are in UTC
- Proper error handling for:
  * Invalid product/warehouse IDs
  * Insufficient stock
  * Invalid transaction types
  * Invalid date ranges
